# Классификация МРТ головного мозга

Обучение CNN для четырёх классов: глиома (`glioma`), менингиома
(`meningioma`), отсутствие опухоли (`notumor`), опухоль гипофиза (`pituitary`).
В ноутбуке рассчитываются precision и recall по каждому классу (цель — не ниже 0.85).

Работа идёт в два шага:

1. `data_prep/dataset.ipynb` — разбор и чистка датасета: состав, копии одних и тех же снимков,
   ошибки разметки, разбиение на train/val/test. Сохраняет манифест `_work/manifest.csv` —
   готовый набор, где каждый снимок встречается один раз.
2. `model.ipynb` — аугментация, обучение и оценка по манифесту.

## Состав

```text
dataset/                 датасет: снимки из четырёх источников (см. ниже)
data_prep/               разбор датасета (шаг 1)
  dataset.ipynb          разбор и сохранение манифеста
  scan.py                поиск снимков в dataset/
  duplicates.py          похожие снимки: копии одного снимка и группы
  split.py               чистка, разбиение train/val/test и манифест
mri/                     обучение (шаг 2)
  config.py              все настройки: пути, классы, источники, разбор датасета, гиперпараметры
  preprocess.py          grayscale, обрезка полей, размер 224×224
  augment.py             аугментации на NumPy: none, A, B, AB, R
  data.py                чтение манифеста и загрузка снимков в память
  balance.py             балансировка классов при обучении (WeightedRandomSampler)
  model.py               свёрточная сеть SimpleCNN
  train.py               Dataset для PyTorch, обучение, предсказания, метрики
tests/                   проверки аугментации (сравнение с OpenCV), поиска почти одинаковых снимков,
                         разбиения и балансировки
model.ipynb              запуск обучения и таблицы результатов (шаг 2)
_work/                   всё создаваемое при работе; в git не попадает (см. ниже)
requirements.txt         зависимости
DATASET_LINKS.txt        источники данных и лицензии
```

Всё, что создаётся при работе — результаты обучения, таблицы и
временные проверки — складывается только в `_work/`. Папка исключена из git
и может быть удалена целиком; в корне проекта и в `dataset/` мусор не появляется.

Все настройки — в `mri/config.py`, включая гиперпараметры обучения (словарь `TRAIN`:
эпохи, batch, expand, скорость обучения, weight decay, dropout, seed). `model.ipynb`
читает их оттуда; для разового эксперимента их можно переопределить в первой ячейке.

## Данные

Датасет один, но собран из четырёх источников — по папке на каждый:

```text
dataset/<источник>/
  Training/<класс>/
  Testing/<класс>/
```

Источники и уровень аугментации для их Training задаются словарём `SOURCES`
в `mri/config.py`: сейчас у всех источников уровень R. BDNeuro раньше был без
аугментации, потому что в нём есть авторская; после чистки её копии исключены.
Чтобы добавить источник, положите его папку в `dataset/` и допишите строку в `SOURCES`.

В проверенной локальной версии:

| Источник | Training | Testing | Всего |
|---|---:|---:|---:|
| PMRAM | 1203 | 302 | 1505 |
| MultiClass | 910 | 227 | 1137 |
| BDNeuro | 5052 | 889 | 5941 |
| KaggleBrainTumor (версия 2) | 5600 | 1600 | 7200 |
| **Всего** | **12765** | **3018** | **15783** |

PMRAM и MultiClass разделены примерно 80/20 по классам, seed 42;
точные копии сгруппированы, но все файлы сохранены.
У BDNeuro исходные train и val объединены в Training, исходный test — в Testing.
У KaggleBrainTumor сохранены исходные Training/Testing версии 2 без переразбиения.

Проверка SHA-256 после добавления выявила 3315 групп точных совпадений между
источниками и 900 групп с участием KaggleBrainTumor, пересекающих Training/Testing.
Побайтные копии — лишь малая часть повторов; полный разбор и чистка — ниже.
Идентификаторы пациентов недоступны, поэтому вместо разделения по пациентам
используются группы похожих снимков.

### Копии снимков и чистка (`data_prep/`)

SHA-256 находит только побайтные копии. `data_prep/duplicates.py` сравнивает уменьшенные
32×32 копии снимков как есть, отражёнными и повёрнутыми на 180° (корреляция). Два уровня,
пороги проверены глазами (`mri/config.py`):

- **один и тот же снимок** (`SAME_IMAGE_THRESHOLD` = 0.98): пересохранённый, отражённый,
  обрезанный иначе, с шумом или другим контрастом;
- **группа** (`NEAR_DUP_THRESHOLD` = 0.97, по цепочке): тот же снимок или соседние срезы той же
  серии, то есть, скорее всего, тот же пациент.

Что нашлось на всех 15783 файлах:

- разных снимков только 6780 (43 %): источники в значительной мере собраны из одних и тех же
  снимков (83 % файлов Kaggle и 71 % BDNeuro есть и в другом источнике);
- BDNeuro и часть Testing KaggleBrainTumor (`Te-aug-*`) содержат авторскую аугментацию:
  отражения, повороты на 180°, шум; варианты одного снимка лежат по обе стороны Training/Testing;
- 8 групп (46 файлов) содержат один и тот же снимок с разными классами (чаще менингиома/гипофиз) —
  ошибки разметки в источниках.

Правила чистки (`data_prep/split.py`); файлы в `dataset/` не меняются, в манифесте
исключённые снимки помечены `split = excluded` и причиной `reason`:

1. группы с разными классами исключаются целиком (`label_conflict`, 46 файлов);
2. от каждого снимка остаётся один файл — без `aug` в имени, затем по источнику
   в порядке `KEEP_PRIORITY` (BDNeuro последним); остальные — `duplicate` (6658 файлов);
3. Training делится на train и val (15 % каждого источника и класса, `VAL_FRACTION`)
   целыми группами;
4. из Testing исключаются снимки, чья группа есть в Training (`seen_in_training`, 2360 файлов):
   модель видела этот снимок или соседний срез.

Итог — 6719 снимков: train 5202, val 930, test 587. Группы train, val и test не пересекаются,
поэтому метрики на test честные. Test небольшой (101–206 снимков на класс), поэтому у метрик
заметная погрешность: при 100 снимках класса recall 0.85 известен примерно ±0.07.

## Установка и обучение

Команды выполняются из корня проекта. Нужен Python 3.10 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyterlab
```

Сначала откройте `data_prep/dataset.ipynb` и выполните ячейки по порядку (около минуты):
он разберёт и почистит датасет и сохранит манифест `_work/manifest.csv`. Манифест одинаков при каждом запуске;
после изменения датасета или настроек разбора выполните ноутбук заново.

Затем откройте `model.ipynb` и выполните ячейки по порядку. Одна CNN обучается
на train всех источников (уровень R, expand 3), 30 эпох; после каждой эпохи
в `history.csv` пишутся метрики на val, test оценивается после обучения.

Классы в train неравны (glioma примерно в 2.3 раза чаще notumor), поэтому при обучении
они балансируются (`balance_classes` в `TRAIN`, код и объяснение — `mri/balance.py`):
снимки редких классов берутся чаще, и за эпоху каждого класса примерно поровну.
Каждый повтор — новый вариант аугментации; разных снимков от этого не прибавляется.
Val и test не балансируются.
Результаты, веса и история сохраняются в `_work/results/<дата_время>/`:
`config.json`, `history.csv`, `model.pt`, `predictions.csv`, `summary.csv`,
`metrics_by_class.csv`, `confusion_matrix.csv`.
При ошибке рабочих процессов DataLoader на Windows поставьте `NUM_WORKERS = 0`.

Проверки (около секунды):

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

Лицензии исходных датасетов и ссылки на авторов указаны в `DATASET_LINKS.txt`.
